# 0070 — NDR adopts hybrid architecture: swamp canonical, vault as projection

## Decision

Swamp becomes the canonical substrate for decision atoms — typed schema, methods, workflows, queries, drift audits — and the Obsidian vault becomes a read surface regenerated by a `vault-sync` report. Markdown is a projection, not the substrate.

## Commitments

- `@jdh313/ndr/decision` (and sibling `@jdh313/ndr/taxonomy`) become the write path; direct markdown edits are no longer authoritative.
- Vault files are regenerated by the `vault-sync` report; edits made directly to markdown are overwritten on the next sync.
- Cross-vault wikilinks (Mulling/, project pages) stay opaque strings; only in-swamp artifact references become typed pointers.
- Round-trip integrity on all 69 existing atoms is the gate between Phase 1 and Phase 2 — if it fails, the existing plugin path stays authoritative.
- If swamp is later removed, the markdown projection stays readable, but workflow integrations (drift-check, supersession enforcement) revert to today's plugin scripts.

## Revisit if

- Any atom fails round-trip parse+emit — the migration halts and this decision is on hold until the gap is closed.
- The `vault-sync` report produces non-deterministic output (timestamp injection, ordering drift) — fix the report before promoting swamp as canonical.

## Context

- Decision atoms had accumulated structural weight — supersession enforcement, drift-check, cross-model references, a validator layered on `persist.py` — that a note-shaped substrate cannot uphold without bespoke Python glue.
- The open question was whether decisions are knowledge artifacts that happen to need some structure, or structured operational artifacts that happen to render to markdown.
- 69 existing atoms lived as vault markdown at the time.

## Why

The supersession work, the drift-check workflow, and the validator layered on `persist.py` each answered the framing question the same way: atoms are operational artifacts. Swamp provides schema enforcement at persist time — an invalid atom cannot be written, not merely flagged — and turns cross-model references into typed pointers (Decision → Proxmox VM artifact by swamp id) rather than opaque wikilink strings. The vault read surface is preserved because a `vault-sync` report regenerates `~/Loose Ends/Decisions/*.md` from swamp data, so human workflows are unchanged; only the write path moves to `swamp model method run`.

## Alternatives

- **Vault-stays-canonical (0007)** — rejected: every new invariant (alias uniqueness, supersession integrity, cross-model references) needs another Python validator bolted onto `persist.py`; swamp gives these as first-class method constraints, and a note-shaped substrate cannot scale this without becoming a bespoke database with worse ergonomics.
- **Schema-only migration (Zod without workflow primitives)** — rejected as a half-measure: gains type safety but loses the method-time enforcement and workflow primitives that justify the migration; not a stable resting point.

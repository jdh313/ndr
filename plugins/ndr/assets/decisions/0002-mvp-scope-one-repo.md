# 0002 — MVP scope = one repo; substrate decision deferred

## Decision

The MVP is a single personal-discipline repo. The substrate question (Decision 0001) is deferred until the discipline has been validated by use.

## Commitments

- Team-product architecture (0001) is preserved but deferred, not abandoned.

## Context

- Q1 ("does this discipline help me?") is upstream of any substrate choice.
- Building the team product first is speculative — settling substrate before discipline is validated risks building the wrong thing twice.

## Why

Personal-discipline tooling comes first because it's the cheaper, faster path to answering Q1; the substrate question only becomes well-posed once Q1 has data to constrain it.
